# TabTidy

找出重复网址和相似标题，按自然顺序或打开时间排列，输出供人工确认的预选结果。

提供 Windows 桌面应用、Chrome / Edge 配套扩展，以及独立 JavaScript core。core 本身无第三方依赖；桌面运行与打包使用 Electron。

## Windows 桌面版

面向 Windows 10/11 x64，便携版解压后运行 `TabTidy.exe`。保留整个应用文件夹，不能只复制 exe。个人测试版尚未代码签名，Windows 可能提示发布者未知。

首次连接，每个浏览器各做一次：

1. 打开桌面应用，点击左侧“打开扩展文件夹”。
2. Chrome 打开 `chrome://extensions`；Edge 打开 `edge://extensions`，开启“开发者模式”。
3. 点击“加载已解压的扩展”（Edge 可能显示“加载解压缩的扩展”），选择刚才打开的 `browser-extension` 文件夹。
4. 回到桌面应用，点击“复制连接码”；再点击浏览器工具栏中的 TabTidy 扩展，粘贴连接码并选择“连接并同步标签页”。

在桌面端查看候选组、调整排序、人工勾选，再“导出已选项”。所有操作均不会关闭浏览器中的标签页。

扩展只读取普通窗口的标题、网址和标签页编号，仅发往本机 `127.0.0.1:37843`；不读取页面正文、Cookie、历史记录，不采集隐身窗口。连接码保存在本机用户配置及扩展存储中，请勿分享。

首次同步后，标签页创建、关闭、标题或网址变化会触发更新。桌面应用重启后，请在扩展弹窗再次点击同步。来源卡片显示的是最近同步快照及时间；浏览器退出时的最后状态不保证送达，不能把旧快照当作仍然打开的实时列表。

浏览器无法提供可靠的原始打开时间，配套扩展把它标为未知；时间排序仍可使用，但这些组不会自动预选。同步时间仅用于显示来源状态。后续同步会保留手动勾选，主动切换排序则重新预选。

### 从源码运行与打包

开发环境需要 Node.js 22.12+：

```sh
npm ci
npm start
npm run package:win
```

Windows 便携文件夹输出至 `dist/TabTidy-win32-x64/`，扩展位于其中的 `resources/browser-extension/`。如果 npm 的安全策略跳过 Electron 安装脚本，可执行 `node node_modules/electron/install.js` 完成运行时下载。

测试：

```sh
npm test
npm run test:desktop
```

桌面测试启动真实 Electron 窗口，使用模拟浏览器接口/同步数据验证交互；不等同于 Windows 实机 Chrome / Edge 的安装验证。

## 运行

只使用独立 core 或 CLI 时无需安装桌面依赖，在项目目录运行：

```sh
npm test
npm run demo
node cli.js examples/tabs.json time desc
node cli.js examples/tabs.json natural asc
```

将示例文件路径替换为自己的 JSON 清单即可。输出写到终端，可重定向保存；读取或校验失败时返回非零状态，错误写入 stderr。

## 使用 core

```js
import { analyzeTabs } from './src/core.js';

const groups = analyzeTabs([
  { id: 'old', title: '某某书 第9章 出发', openedAt: 1000 },
  { id: 'new', title: '某某书 第10章 重逢', openedAt: 2000 },
], { sortBy: 'natural', direction: 'desc' });
```

结果：

```json
[
  {
    "reasons": ["similar-title"],
    "tabs": [
      { "id": "new", "title": "某某书 第10章 重逢", "openedAt": 2000, "selected": false },
      { "id": "old", "title": "某某书 第9章 出发", "openedAt": 1000, "selected": true }
    ]
  }
]
```

输入字段：

| 字段 | 约定 |
| --- | --- |
| `id` | 必填且唯一，非空字符串或非负安全整数；数字 `1` 和字符串 `"1"` 是不同 ID |
| `title` | 必填字符串；空标题不参与标题匹配，仍可按网址归组 |
| `url` | 可选的绝对网址字符串；空字符串、null 或省略表示未知 |
| `openedAt` | 可选的非负安全整数，单位为毫秒；null 或省略表示未知 |

选项只有 `sortBy`（`natural` / `time`）与 `direction`（`asc` / `desc`），默认为自然降序。core 不修改输入，每个输出标签页都是浅拷贝；已有的 `selected` 会被本次预选结果覆盖。

## 分组与预选规则

- 完整网址相同：原因 `duplicate-url`；查询参数、片段等差异会保留。
- 标题统一全半角、大小写、空白和标点。仅匹配时忽略阿拉伯数字，以及“整理版、更新版、完整版、精校版、修订版”等列出的版本说明；去除后为空时保留原串。原始标题和排序内容保持不变。
- 数字与版本说明变化可归组，例如 `xxx1` / `xxx1-2`、`某某书 1–20` / `某某书 1–30`、`星河旅行 1-20 整理版` / `星河旅行 1-30 更新版`。
- 标题包含“书名 第N章/节/回/卷/集/部”时，用前面的书名匹配，因此章节号与后续章节名可以不同；这里的 N 可以是阿拉伯数字或常见中文数字。
- 其他标题在归一化后均至少 4 个字符时，满足以下任一条件即可列为候选：相邻字符对集合的 Dice 相似度至少 0.8；或存在共同连续文字片段，片段至少 4 个字符，且覆盖较长标题的至少一半。长度按 Unicode 字符计算。
- 因此支持部分文字增删和顺序调整，例如 `前端入门指南` / `指南前端入门`、`星河旅行 甲整理` / `乙分享 星河旅行`；无需统一命名格式。
- 不区分网站。候选关系可传递，例如 A 与 B 标题相似、B 与 C 网址重复，则三者归为一组；一组内任意两项不一定直接相似。
- 只输出至少两个标签页的候选组；组间保持各组首次出现在输入中的顺序，排序作用于组内。
- 自然排序用标题中的连续阿拉伯数字比较数值，例如 `第2章 → 第10章`；不推断章节进度或解析中文数字的大小。
- 一般保留组内排序后的第一项（`selected: false`），预选其余项（`selected: true`）。升序会优先保留较小/较旧的项，降序优先保留较大/较新的项。
- 时间排序时未知时间始终在末尾，并列保持输入顺序；组内有未知或并列时间时，整组全部 `selected: false`，交给人工选择。

打开时间必须来自可靠的数据源，不能拿浏览器恢复时刻或最后访问时间冒充。core 不负责采集、补推或持久化时间。

标题匹配只是检查线索：共同的长站点后缀、通用文字及相似书名都可能造成误分组；同义改写但文字不同也可能漏分组。结果需要人工确认。core 使用两两比较，适用于个人标签页清单；没有面向超大数据集优化。
